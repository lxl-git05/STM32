## 1. 最终目标

学完本计划后，应当能够独立完成下面这些工作，而不是只会复制一份点灯例程：

1. 从空目录开始，在 CubeMX 中选择 STM32F407ZGT6，配置时钟、SWD、GPIO、串口、DMA、中断和 FreeRTOS，并生成可编译、可下载、可调试的工程。
2. 解释任务的 Running、Ready、Blocked、Suspended 状态以及抢占、时间片、优先级和上下文切换。
3. 正确选择任务、队列、任务通知、信号量、互斥量、事件组、软件定时器、Stream Buffer 和 Message Buffer。
4. 正确处理 ISR 与任务之间的通信，理解 `FromISR` API、中断优先级限制和中断退出时的任务切换。
5. 分析任务栈、RTOS Heap、CPU 占用率和执行时间，定位栈溢出、死锁、优先级反转、竞态、阻塞和时序抖动。
6. 将本 PCB 上的按键、EC11、OLED、串口 DMA、MPU6050、AT24C02、ADC、直流电机、编码器、步进电机和视觉通信逐步接入 FreeRTOS。
7. 将现有“超级循环 + 定时器 Tick + Mode 状态机”工程迁移成事件驱动的多任务系统，同时保留硬件定时器产生 PWM/计步等真正需要硬实时的部分。
8. 独立完成最终综合项目，并能说明每个任务为什么存在、为什么采用当前优先级、任务之间为什么使用这种通信机制。

“学完所有操作”在本计划中指覆盖 FreeRTOS 单核 MCU 项目最常用且重要的完整能力。已经弃用的 Co-routines、SMP 多核特性和安全认证版本不作为 STM32F407 入门主线。

## 2. 学习原则

### 2.1 每个阶段只增加一个新变量

遵守下面的固定节奏：

```text
阅读概念 → CubeMX 配置 → 写最小代码 → 编译 → 下载 → 观察现象
        → 制造一次错误 → 用调试器定位 → 写实验记录 → Git 提交
```

不要第一天就把原模板的所有驱动复制进 RTOS 工程。现有模板一次初始化 OLED、串口、EEPROM、电机、步进电机、IMU 等模块，不利于判断故障来源。

### 2.2 每个实验都必须有验收证据

至少保留以下一种证据：

- LED、蜂鸣器或电机的可观察现象；
- 串口日志；
- 逻辑分析仪/示波器波形；
- 调试器中的任务状态、队列状态、栈余量；
- 运行时间、周期抖动或错误计数数据。

仅仅“编译通过”不算完成。

### 2.3 不在中断里做业务

中断负责采样、清标志、保存最少量数据并唤醒任务；协议解析、OLED 刷新、I2C 读写、浮点融合和长循环放到任务中。步进脉冲计数等真正需要低抖动的极短操作可保留在硬件定时器 ISR。

### 2.4 同一共享资源只有一个主人

优先采用“服务任务 + 消息队列”：

- OLED 只由显示任务刷新；
- UART TX 只由日志/发送任务操作 DMA；
- EEPROM 只由存储任务写入；
- 控制输出只由控制任务更新。

确实需要多个任务直接访问同一外设时才使用 Mutex。不能用全局关中断代替任务互斥。

### 3.6 必须先解决的冲突

1. **TIM6 冲突**：通用教程常让 HAL 使用 TIM6，而原模板已经用 TIM6 做 1 ms 业务节拍。干净学习工程可以用 TIM6；最终迁移旧模板时，应先把按键扫描、LED 闪烁和步进 ramp 迁到 RTOS 周期任务，再释放 TIM6 给 HAL；或者选择经审计后确定空闲的 TIM5/TIM13/TIM14 作为 HAL 时基。
2. **NVIC 不兼容**：原模板是 `NVIC_PRIORITYGROUP_2`，大量 DMA/UART/TIM/EXTI IRQ 使用数值优先级 0，步进 IRQ 为 1。接入 FreeRTOS 后应统一改为通常使用的 Group 4；凡 ISR 调用 RTOS API，IRQ 数值必须落在 `FreeRTOSConfig.h` 允许的范围内，常见是数值不小于 5，但最终以生成配置为准。
3. **48 MHz 域错误**：原 `.ioc` 的 PLLQ 输出是 84 MHz。学习工程使用 M=8/N=336/P=2/Q=7，防止以后 USB、SDIO 或 RNG 阶段被时钟卡住。
4. **PB5 冲突**：PB5 当前是 LED0，旧资料又把它规划成 LCD SPI 数据线；当前 SPI3 也没有完整初始化。学习主线保持 PB5 为 LED，LCD 另行做引脚审计。
5. **I2C2 标签反写**：硬件复用实际是 PF0=SDA、PF1=SCL，但当前宏名相反。不能按宏名盲目接线。
6. **预留 AF 不等于启用外设**：PC6/PC7 USART6、PA8/PC9 I2C3、PB3 SPI3_SCK 只有引脚占位，没有完整外设初始化。
7. **资料版本冲突**：PE11 当前是电磁阀 GPIO，不是舵机 PWM；寻迹引脚含义也与旧表不一致；RGB 的颜色映射需实测。
8. **现有阻塞代码**：OLED 软件 I2C、AT24C02 写周期、串口发送等待、IMU 初始化/标定都包含忙等或长超时，不能直接搬进高优先级任务或 ISR。
9. **共享变量竞态**：EC11 计数读后清零、UART DMA 接收结构体、Y8 数组、OLED 显存、电机/PID 状态都需要重新设计所有权和同步。

## 5. API 学习路线

CubeMX 中 FreeRTOS 选择 `CMSIS_V2`。前半程用 CMSIS-RTOS2 API 熟悉概念，后半程对照 FreeRTOS 原生 API。不要在同一对象上混用两套句柄和 API。

| 概念 | CMSIS-RTOS2 | FreeRTOS 原生 API |
|---|---|---|
| 创建任务 | `osThreadNew` | `xTaskCreate` / `xTaskCreateStatic` |
| 相对延时 | `osDelay` | `vTaskDelay` |
| 周期延时 | `osDelayUntil` | `vTaskDelayUntil` |
| 消息队列 | `osMessageQueueNew/Put/Get` | `xQueueCreate/Send/Receive` |
| 互斥量 | `osMutexNew/Acquire/Release` | `xSemaphoreCreateMutex/Take/Give` |
| 信号量 | `osSemaphoreNew/Acquire/Release` | `xSemaphoreCreateBinary/Counting` |
| 线程标志 | `osThreadFlagsSet/Wait` | 任务通知 `xTaskNotify...` |
| 事件组 | `osEventFlags...` | `xEventGroup...` |
| 软件定时器 | `osTimer...` | `xTimer...` |

原生 API 转换实验应单独复制工程完成。目的不是追求 API 数量，而是理解 CMSIS 适配层和 FreeRTOS 内核对象之间的关系。

## 6. 分阶段项目路线

按每周 6～10 小时估算，完整主线约 16～20 周。时间不足时按“验收通过再进入下一阶段”，不要按日历强行赶进度。

### 阶段 0：裸机硬件基线——从零建立 CubeMX 工程

**目标**：证明芯片、时钟、SWD、LED、按键和调试串口都正常。

**CubeMX 步骤**：

1. New Project → MCU Selector → 搜索并选择 `STM32F407ZGT6`。
2. RCC → HSE 选择 `Crystal/Ceramic Resonator`。
3. SYS → Debug 选择 `Serial Wire`。
4. Clock Configuration：HSE=8 MHz，PLLM=8、PLLN=336、PLLP=2、PLLQ=7；AHB=/1、APB1=/4、APB2=/2。
5. PB5 配成 `GPIO_Output`，标签 `LED0`。
6. PE4、PE3 配成上拉输入，标签 `KEY0`、`KEY1`。
7. USART1 使用 PA9/PA10，115200、8N1；第一步先阻塞发送，不开 DMA。
8. 工程设置开启 `Keep User Code when re-generating`，按外设生成 `.c/.h`，生成工程。
9. 先做 `HAL_Delay` 点灯、按键读取和串口输出。

**必须理解**：启动文件、`HAL_Init`、`SystemClock_Config`、GPIO 初始化、APB 定时器倍频、`USER CODE` 区域、编译/链接/下载流程。

**验收**：

- 调试器可暂停在 `main`；
- PB5 每 500 ms 翻转；
- 按键能改变闪烁模式；
- USART1 连续输出时钟频率和按键事件；
- 能解释为什么 APB1=42 MHz 而 APB1 定时器时钟是 84 MHz。

### 阶段 1：第一个 FreeRTOS 工程

**目标**：让 LED 在任务中闪烁，建立内核启动的完整心智模型。

**CubeMX 增量配置**：

1. SYS → Timebase Source：这个干净工程选择 TIM6。
2. Middleware → FreeRTOS → Interface：`CMSIS_V2`。
3. 使用抢占调度，Tick Rate 1000 Hz，Heap 先用 `heap_4`，Total Heap 先设 16 KB。
4. 创建 `LedTask`，Normal 优先级，栈先给 512 Bytes（若界面单位为 Words，则填 128 Words）。
5. 生成代码，检查 `osKernelInitialize`、对象创建、`osKernelStart` 的顺序。

任务循环使用 `osDelay(500)`，不再用 `HAL_Delay(500)`。

**必须理解**：SysTick 给 RTOS，TIM6 给 HAL；空闲任务；任务函数为什么通常不返回；Tick、调度器和 PendSV 的关系。

**验收**：删除/注释任务内延时后，能够解释 CPU 被占满的原因；能在调试器中看到任务栈和任务状态。

### 阶段 2：调度、优先级与任务状态

**项目**：用 PB5 和 RGB 创建三个不同周期任务；按键动态改变其中一个任务的优先级。

**学习内容**：Ready/Running/Blocked/Suspended、抢占、同优先级时间片、`yield`、任务创建/删除/挂起/恢复、优先级饥饿。

**故障实验**：创建一个高优先级无限空转任务，观察低优先级 LED 停止，再通过阻塞等待修复。

**验收**：不看资料画出三任务状态切换图，并说明“优先级高”不等于“获得更多固定时间片”。

### 阶段 3：周期任务与时间确定性

**项目**：

- 5～10 ms 按键扫描任务；
- 20 ms RGB 状态任务；
- 500 ms 心跳任务；
- 用 DWT 或逻辑分析仪测量周期。

**学习内容**：`osDelay`/`vTaskDelay` 与 `osDelayUntil`/`vTaskDelayUntil` 的区别、周期漂移、deadline、jitter、WCET。

将原模板 `Hardware/Key.c` 的 1 ms Tick 调用方式迁入周期任务。不要在定时器 ISR 中执行完整按键状态机。

**验收**：运行一分钟后，周期任务没有持续累积漂移；记录最大/最小周期和一次超期原因。

### 阶段 4：队列——按键事件驱动 LED/RGB

**项目**：按键扫描任务只产生 `{key, event, timestamp}` 消息；LED 管理任务从队列阻塞接收并改变灯效。

**学习内容**：队列复制语义、长度和元素大小、阻塞超时、满/空处理、`send to back/front`、`peek`、单槽覆盖、Queue Set 的适用边界。

对比原模板的 `Software/Queue.c` 环形队列：理解它为什么在多任务/ISR 并发下不是天然安全的。

**故障实验**：把消费者故意延迟，制造队列溢出；加入丢包计数和高水位记录。

**验收**：没有使用“多个任务轮询同一个全局按键标志”；队列满时行为明确且可观测。

### 阶段 5：EXTI 与任务通知——EC11

**项目**：PF3/PF7 EXTI 中断记录 EC11 增量，用任务通知或队列唤醒 `InputTask`，在任务里完成去抖和累计。

**学习内容**：`FromISR` API、`xHigherPriorityTaskWoken`、中断退出触发切换、通知的覆盖/递增/置位模式、原子性与短临界区。

原代码 `Encoder_Count` 存在 ISR 写、任务“读取后清零”的竞态窗口。练习使用临界区或通知累加值解决，不能只添加 `volatile` 就宣布线程安全。

**验收**：快速旋转不明显丢计数；ISR 中没有 OLED、串口格式化或延时；能解释为什么 Mutex 不能在 ISR 中使用。

### 阶段 6：共享资源、Mutex 与优先级反转

**项目 A**：两个任务同时打印 USART1，先观察日志交叉，再通过 UART 日志服务任务解决。  
**项目 B**：OLED 只允许 `DisplayTask` 修改 1 KB 显存和刷新总线，其他任务发送显示消息。

**学习内容**：Mutex、递归 Mutex、优先级继承、二值信号量与 Mutex 的区别、死锁、锁顺序、锁粒度、单一所有者模式。

**故障实验**：构造低优先级任务持锁、中优先级任务占 CPU、高优先级任务等待锁的优先级反转场景。

**验收**：多任务日志不交叉；OLED 不再由多个任务直接刷新；不存在持锁期间 `osDelay`、长 I2C 超时或等待另一个锁。

### 阶段 7：二值/计数信号量与事件组

**项目**：

- EXTI 或 DMA 完成中断释放二值信号量；
- 用计数信号量模拟有限缓冲块池；
- 用事件组表示 `SENSOR_READY | UART_READY | STORAGE_READY | MOTOR_SAFE`；
- 系统管理任务等待必要条件齐备后进入运行态。

**学习内容**：同步与数据传输的区别、事件位 Any/All、自动清除、事件组不能替代携带数据的队列。

**验收**：能够为“来了一个事件”“来了 20 字节数据”“保护 I2C”“等待三个模块就绪”分别选择正确对象。

### 阶段 8：软件定时器与蜂鸣器服务

**项目**：实现一次性按键确认音、周期心跳音和可取消告警；LED 模式从手写计数器迁到软件定时器或周期任务并比较。

**学习内容**：一次性/自动重装定时器、Timer Service Task、Timer Command Queue、回调限制。

**规则**：定时器回调必须短小、不能永久阻塞；回调只更新轻量状态或发送消息。

**验收**：同时启动多个定时器仍能解释实际执行回调的是哪个任务，以及为什么回调优先级由 Timer Task 决定。

### 阶段 9：UART DMA + Idle + Stream Buffer

**项目**：将 USART1 接收改为 `HAL_UARTEx_ReceiveToIdle_DMA`：ISR 只提交字节流，`ParserTask` 负责 ABC/HEX 帧解析，`LogTask` 独占 TX DMA。

**学习内容**：DMA 生命周期、Idle 事件、双缓冲/环形缓冲、Stream Buffer 与 Message Buffer、零拷贝的收益和所有权风险、Cache 不相关但内存可见性仍需考虑。

参考现有代码：`Function/Serial_porting.c`。当前代码在 ISR 回调中直接解析协议，TX DMA 后仍忙等完成；本阶段要把它改造成 ISR→Buffer→任务的流水线。

**验收**：连续突发数据不丢帧；故意发送半帧、粘包、错误长度和错误校验时不会越界或卡死；打印丢字节和解析错误统计。

### 阶段 10：I2C1 + MPU6050 传感器任务

**项目**：`ImuTask` 以固定周期读取 MPU6050，向队列发布带时间戳的数据；另一个任务完成滤波/姿态融合，显示任务只读取结果快照。

**学习内容**：总线 Mutex、传感与计算解耦、生产者/消费者、采样周期、超时和故障恢复、浮点运算执行时间。

原 IMU 代码存在较长轮询超时、标定循环，并可能在定时器回调路径读取 I2C。迁移后初始化/标定放在启动阶段或专门任务中，绝不放进 ISR。

**验收**：拔掉传感器时系统不永久卡死，LED/串口仍能报告故障；能测出采样任务和融合任务的最坏执行时间。

### 阶段 11：AT24C02 异步存储服务

**项目**：其他任务发送“保存参数”请求，低优先级 `StorageTask` 合并短时间内的重复请求并延迟写 EEPROM。

**学习内容**：慢外设服务任务、请求/响应队列、写周期、掉电一致性、校验/version 字段、启动顺序。

参考 `bsp_at24c02.c`、`at24c02_manager.c` 和 `Param_AT24C02.c`。原代码包含写后 `HAL_Delay(5)` 和较长 I2C 超时，不能在 ISR 或高优先级控制任务中调用。

**验收**：频繁旋转 EC11 调参时不会每次变化都立刻写 EEPROM；断电重启能恢复有效参数，损坏数据能回退默认值。

### 阶段 12：ADC/Y8 数据采集

**项目**：先用 PC4 单次 ADC 轮询建立基线，再升级为定时触发 + DMA；处理任务计算滤波值和状态，必要时发布给控制任务。

**学习内容**：DMA 完成/半完成事件、采样缓冲所有权、双缓冲、移动平均、Queue 与任务通知的选型。

Y8 的 PF11/PF13/PF15/PF12 含义与旧文档不一致，开始接线前必须用实际 PCB/协议重新确认。

**验收**：采样频率可测量；处理任务来不及时有覆盖/丢帧策略；DMA 缓冲区不会在处理期间被无控制地改写。

### 阶段 13：内存、栈与故障诊断

**项目**：为全部任务输出栈高水位、剩余 Heap、最小历史 Heap；主动制造一次栈溢出和一次分配失败。

**学习内容**：任务栈单位、TCB、`heap_1`～`heap_5`、动态/静态创建、碎片、`configCHECK_FOR_STACK_OVERFLOW`、Malloc Failed Hook、Idle Hook、Tick Hook、断言和 HardFault 初步定位。

STM32F407 的 CCM RAM 不能被 DMA 访问。后续若调整链接脚本，应明确哪些任务栈/算法数据可以放 CCM，哪些 DMA 缓冲必须留在普通 SRAM。

**验收**：根据实测高水位调整栈，而不是凭感觉统一给很大栈；所有创建函数返回值都被检查。

### 阶段 14：中断优先级与临界区专项

**项目**：将 EXTI、UART/DMA、TIM 中断统一纳入优先级表，验证允许/禁止调用 RTOS API 的边界。

**学习内容**：Cortex-M 数值越小优先级越高、NVIC Group 4、`configPRIO_BITS`、`configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY`、临界区、调度器锁与关中断的区别。

**禁止**：沿用原模板所有 IRQ=0 后在其中调用队列/通知；用长时间 `__disable_irq()` 保护 I2C/OLED/UART。

**验收**：文档化每个 IRQ 的数值优先级、是否调用 RTOS API、调用哪个 `FromISR` API和最坏执行时间。

### 阶段 15：直流电机闭环控制

**安全前提**：先断开负载或限流供电，确认方向、急停、PWM 零值和编码器极性；机械系统留出急停手段。

**项目**：TIM4 产生 PWM，TIM2/TIM3 读编码器；固定周期 `MotorControlTask` 执行速度/位置 PID；命令队列传递目标值；遥测队列输出结果。

**学习内容**：控制周期、优先级分配、deadline、优先级倒置对控制的影响、设定值快照、饱和和失控保护。

**原则**：PWM 和编码器由硬件外设工作；RTOS 负责较低频的控制计算和命令组织。不要用 RTOS 软件定时器产生电机 PWM。

**验收**：测量控制任务周期抖动；通信/OLED 压力增加时控制环仍达标；传感异常或任务超时会输出安全值。

### 阶段 16：步进电机与硬件 ISR 协作

**项目**：TIM9/TIM12 产生脉冲，极短 ISR 计数；上层位置任务管理目标、加减速和限位；命令通过队列进入。

**学习内容**：硬实时脉冲生成与任务调度的边界、ISR 高频开销、通知合并、共享位置原子快照、安全停止。

高频每脉冲 ISR 不应发送复杂队列或打印日志。若 ISR 确实调用 RTOS API，先把原来手设的优先级 1 改到允许 syscall 的范围。

**验收**：高串口流量、OLED 刷新和 EEPROM 保存期间不丢步；限位触发能在规定时间内停止。

### 阶段 17：系统监控、看门狗与运行统计

**项目**：每个关键任务周期性提交健康标志，由 `SupervisorTask` 聚合；所有关键任务健康时才喂 IWDG。

**学习内容**：软件 watchdog 模式、CPU 运行时间统计、任务列表、栈水位、故障码、复位原因、日志限流。

**验收**：人为挂死某任务后系统停止喂狗并重启；重启后能报告上次故障来源，而不是无条件喂狗掩盖故障。

### 阶段 18：迁移现有模板架构

现有模板是：

```text
main 超级循环 + Mode 状态机
TIM6 1ms Tick + TIM7 20ms Tick + TIM10 10ms Tick
多个 HAL 弱回调集中分发
```

目标架构建议为：

```text
EXTI / UART DMA / Timer ISR
       │ 只采样、清标志、通知
       ▼
InputTask / CommRxTask / SensorTask
       │ Queue / Notification / Event Flags
       ▼
ModeManagerTask ──→ ControlTask ──→ PWM/Direction
       │                   │
       ├──→ DisplayTask    └──→ Telemetry Queue
       └──→ StorageTask           ↓
                                LogTask
```

迁移顺序：

1. 保留原驱动文件，只建立模块清单和共享资源清单。
2. 把 `Key_Tick`、LED Flash 和 20 ms 模式 Tick 迁到周期任务，释放 TIM6/TIM7 的业务职责。
3. 保留 TIM9/TIM12 步进脉冲 ISR，但缩短回调。
4. UART Idle 回调改成只投递数据，解析移到任务。
5. OLED 改为单显示任务。
6. AT24C02 改为存储服务任务。
7. Mode 状态机保留为 `ModeManagerTask`，状态变更通过消息触发。
8. 合并唯一的 `HAL_TIM_PeriodElapsedCallback`、`HAL_GPIO_EXTI_Callback`、`HAL_UARTEx_RxEventCallback`，不能在多个文件重复定义强符号。
9. 重新规划全部中断优先级并完成压力测试。

**验收**：不存在业务依赖 1 ms 大中断回调链；不存在主循环无界轮询；模块之间通过明确接口通信。

### 阶段 19：最终综合项目——双轴控制终端

建议最终项目包含：

- EC11/按键输入与模式管理；
- OLED 参数与状态显示；
- USART1 调试日志；
- USART2 香橙派视觉数据；
- IMU 数据采集与姿态发布；
- AT24C02 参数异步持久化；
- 直流电机或双轴步进控制；
- 系统监督、故障状态、看门狗和运行统计。

建议任务表起点如下，最终优先级必须根据实测 WCET 和 deadline 调整：

| 任务 | 触发方式 | 初始优先级思路 | 主要通信 |
|---|---|---|---|
| MotorControlTask | `vTaskDelayUntil`/硬件采样通知 | 高 | 命令队列、遥测队列 |
| SensorTask | 周期或 DRDY 通知 | 较高 | 数据队列 |
| CommRxTask | UART DMA/Idle 通知 | 较高 | Stream Buffer、命令队列 |
| ModeManagerTask | 阻塞等待事件 | 中 | 队列、事件组 |
| InputTask | 周期/EXTI 通知 | 中 | 输入事件队列 |
| DisplayTask | 阻塞等待更新，限频刷新 | 低 | 显示消息队列 |
| StorageTask | 阻塞等待保存请求 | 低 | 请求队列、I2C Mutex |
| LogTask | 阻塞等待日志 | 低 | 日志队列、TX DMA |
| SupervisorTask | 固定周期 | 中高 | 健康位、事件组 |

最终验收必须包含：

1. 连续运行至少 8 小时，无断言、栈溢出和 Heap 持续下降。
2. UART 连续突发、频繁按键/OLED 刷新、参数保存同时发生时，控制任务仍满足周期要求。
3. 传感器断开、UART 错帧、队列满、EEPROM 超时和任务失联都有可恢复或安全停机策略。
4. 输出任务表、IRQ 优先级表、内存预算、CPU 占用、最坏周期抖动和故障测试记录。
5. 能脱离代码解释整个数据流以及每个同步对象的选择理由。

## 10. 可选：真正的网络通信方向

如果“网络相关资源”也包括 TCP/IP 学习，可在主线完成后增加这一阶段。

STM32F407 自带 Ethernet MAC，但当前模板没有启用 ETH/LwIP，也没有证据证明该 PCB 已安装 PHY、RJ45、50 MHz 参考时钟及完整 RMII/MII 网络。大量 ETH 复用引脚当前还被电机、ADC、UART 等功能占用，因此不能仅凭 MCU 支持 Ethernet 就开始配置。

可选路线：

1. 先确认 PCB 原理图是否有 LAN8720/DP83848 等 PHY 和 RMII 网络。
2. 若硬件具备网络，先建立独立 ETH + LwIP 裸机 Ping 工程，再接入 FreeRTOS。
3. 将网络输入交给通信任务，不在 LwIP 回调里直接控制电机。
4. 学习 DHCP、静态 IP、UDP、TCP server、断线重连、超时和缓冲区背压。
5. 若 PCB 没有 PHY，优先沿用 USART2 与香橙派通信；也可另行评估 SPI 以太网或 UART/SPI Wi-Fi 模块，但要先解决 PB5/LCD/SPI 等引脚冲突。

网络不是 FreeRTOS 内核入门的前置条件，应放在任务、队列、同步、ISR、内存和调试都掌握之后。

## 11. 现在立刻开始的第一项任务

不要先复制旧模板。现在建立 `00_Board_BringUp`：

1. 新建 STM32F407ZGT6 CubeMX 工程。
2. 配置 HSE 8 MHz 和 168 MHz 标准时钟树，确保 48 MHz 域正确。
3. 开启 SWD。
4. 只启用 PB5 LED、PE4/PE3 按键和 USART1 PA9/PA10。
5. 生成、编译、下载。
6. 完成 LED 闪烁、按键改变周期、串口输出三项裸机验收。
7. 写 `00_Board_BringUp/README.md`，记录实际 LED/按键有效电平和晶振验证结果。

第一阶段的意义是建立可信硬件基线。若连裸机 LED 和串口都没有验证，启用 RTOS 后出现无输出，将无法判断问题来自时钟、下载、引脚、HAL 还是调度器。
